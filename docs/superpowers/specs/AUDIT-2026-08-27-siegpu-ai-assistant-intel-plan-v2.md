## 次要观察（不强制修改，实施时注意）

1. 自动别名并发插入撞唯一索引 → IntegrityError 按「已存在」处理（转 usage_count+1），不炸链路；
2. 确认卡重载后状态丢失（history 只回放文本）——M1 可接受，卡片状态以服务端 token 行为准；
3. draft_billing 的参数面（device 解析）复杂度高于其他动作——默认关，实施时 dry_run 强制 device_id 前置解析；
4. eval 的 fastpath 确定性测试需 db fixture（capital/count 意图），guide 意图可 db=None——B2 已注明；
5. R4 prompt 膨胀：eval 每题记录 prompt token，基线 +30% 为告警线——已入风险登记册。

## 结论

v1.1 的三项目设计经对抗推演后闭环：唯一实质缺口（D16 认知归因）已补，安全不变量从 6 条扩至 8 条（原子认领 + 角色门槛）。**计划书 v1.2 可作为实施基线。**
