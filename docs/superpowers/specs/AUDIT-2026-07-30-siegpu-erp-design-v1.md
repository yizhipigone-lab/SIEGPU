## 6 维度结论

### 维度 1 — 完整性：【结论：FAIL】

核心覆盖情况：三大痛点（资金池/金租/对账）的主体表都在，金租 9 节点、跨项目调配、折旧 5 年/10% 残值等有体现。但财务系统几个"必须有"的东西大面积缺失。

1. **【FAIL §3.2 / §4.6 行 268-282、455】无计费/收入确认表（billing/revenue）**
   - §4.6 明确写"点亮验收日 = 计费起点……之后按固定月租"，但 13/15 张表里没有 billing 表。
   - 月租收入唯一可能的落脚点是 `capital_transactions.source_type='租金收入'`，这只记"现金流入"，不记"应收账款/营业收入"。
   - 后果：客户拖延付款时，应收和收入确认无账可记，月结和利润测算拿不到权责发生制口径。

2. **【FAIL §3.2 全节】无 users 表，多个外键悬空**
   - §5.2 描述了用户账号、4 角色、JWT、角色中间件，但表清单里没有 users。
   - 以下 UUID 字段全部 FK 悬空：`capital_transactions.created_by`、`capital_allocations.approved_by`、`leasing_nodes.owner_id`。DDL 附录 A 也没建 users 表。

3. **【FAIL §3.2 / §4.4 / §4.8】并发与幂等完全未设计**
   - 放款确认 → 生成 capital_transaction；跨项目调配 → 生成 2 条 transaction + 1 条 allocation；点亮 → 生成资产。三条链路都没有 idempotency key、没有唯一约束、没有事务包裹、没有"已生成"标志位。网络重试或双击就产生重复流水，直接污染资金池余额。

4. **【FAIL §3.2 / §9 / §10】软删除与冲红机制缺失**
   - 全表没有 `deleted_at`，文档没提软删除策略。§10 风险表没列"数据录错如何回溯"。财务数据硬删/直改金额，资金池余额会无声变化且无审计。

5. **【WARNING §3.2 / §4.7】还款计划无自动生成 + 金租缺利率字段**
   - §4.7"手动录入还款计划（20 期）"违背 DRY，且与"放款"动作脱节。`leasing_processes` 只有 `total_amount`，没有利率/期数/还款频率字段，自动生成无数据来源。

6. **【WARNING §3.2】税额计算与含税口径未定义**
   - `invoices.tax_amount` 字段在，但没有 tax_rate，没有"金额是否含税"口径。§3.4 对账 SQL 直接用 `i.amount` 跟 `c.amount` 比，若一边含税一边不含税（13%）差异直接爆。

7. **【WARNING §3.2 / §4.8】折旧部分年份逻辑未定义**
   - 年化口径 `÷5`，资产若 2026-09-15 点亮，2026 只能计 3.5 个月，没有月折旧/首年按月规则。`end_date` 无推导公式。

8. **【WARNING §3.2 行 94】表数量声明错误**
   - 标题写"13 张"，实际 15 张（主数据 4 + 项目合同 2 + 资金 2 + 金租 2 + 交付运营 5），还不算应补的 users 表。

### 维度 2 — 一致性：【结论：WARNING】

1. **【WARNING 行 186 vs 273】direction 字段中英文混用** — `capital_transactions.direction=IN/OUT` vs `invoices.direction=收/付`，§5.3 也用 `direction='付'`。
2. **【WARNING 全 §3.2 + 附录 A】时间戳字段不统一** — suppliers 有 created_at/updated_at；多数表（customers/contracts/leasing_*/assets/orders/...）完全没时间戳或只有 created_at。
3. **【WARNING 行 142、307】利率/残值率单位歧义** — `interest_rate DECIMAL(5,4)` 暗示小数（0.0435），`residual_rate` 注释"固定 0.10"也是小数，但文档零说明、无对照表。
4. **【WARNING 全节 status】状态枚举无约束、无流转规则** — 全是 VARCHAR(20) 自由文本，无 CHECK、无状态机。
5. **【WARNING 行 268-282、193】发票与资金流水无外键关联** — 发票 paid_date 记了付款日，但没 capital_transaction_id；对账靠人工脑补。

### 维度 3 — 可行性：【结论：WARNING】

1. **【WARNING §3.3 / §5.3】资金池"共享 vs 子池"模型可工作，但可调余额未定义** — 总余额不分项目、调配净 0 逻辑自洽；但"从 A 调出 500 万"时 A 是否真有 500 万可调无校验，可能调出实际没钱的项目。
2. **【WARNING §4.4 / §3.2】金租放款三处日期无约束** — 节点 actual_date、`disbursement_date`、生成的 transaction_date 三者应一致但无约束保证。
3. **【WARNING §4.5 / §4.8】点亮→资产→折旧起点触发链含糊** — "触发计费起点"未说触发生成资产；"自动/手动"二选一没定；谁触发、API 在哪、PATCH 是否带副作用全断层。
4. **【WARNING §7】4-6 周工期对"团队 Python/前端经验不足"偏紧** — 配合无测试策略风险叠加。

### 维度 4 — 风险识别：【结论：FAIL】

§10 只列 4 条泛泛风险，对财务系统真正的"如果……怎么办"几乎没碰。

1. **【FAIL §10 / §3.2】数据录错如何回溯/冲红——完全没设计** — 手抖把 100 万录成 1000 万怎么改？无冲红凭证、无变更日志、无审批流，配合审计日志放二期，一期内任何财务数据修改无痕。
2. **【WARNING §5.3】调配金额超过可调余额——无校验** — `POST /api/capital/allocate` 无 from_project 余额校验、无上限。
3. **【WARNING §3.4 / §4.6】发票累计超过合同金额——无拦截** — 对账 SQL 只是事后显示差异，录入时不拦截超开。
4. **【WARNING §3.2 / §4.4】金租实际放款与申请额不符——无对账** — `total_amount` 申请额 vs 实际放款进 capital_transactions，两者无 reconciliation。
5. **【WARNING §10 / §8】历史数据初始化风险未量化** — 商机 5090 等项目已在跑，历史流水/发票/还款/资产全量初始化，工作量可能比建新表还大，路线图没列。
6. **【WARNING §4.7】20 期还款与"金租公司流程差异"冲突** — `repayments.period` 写死"1-20=5年×4季"，若某金租要求月付/半年付/3 年期模型装不下。

### 维度 5 — 优先级：【结论：FAIL】

1. **【FAIL §7 行 592】审计日志/操作留痕放二期——对财务系统是致命错位** — 记账、管资金池、算折旧、还金租的系统，资金流水和发票从一期第一天起就是高敏数据。配合无软删除/无冲红，一期全程 edit/delete 无痕。必须挪到一期。
2. **【WARNING §7 / §5.2】角色中间件未明确排期** — "用户认证"笼统塞进周 1-2，4 角色 RBAC 是实打实工作量，应独立列交付项。
3. **【WARNING 全文】状态机设计缺失** — 9 张表有 status 但无流转图/合法迁移表。状态机应作为基础设施先于业务模块设计。
4. **【WARNING §4.7 / §4.4】还款计划生成时点错位** — 业务上"放款确认"应自动生成计划，文档写"手动录入"，放款后到录入间有真空期，逾期预警无数据。
5. **【PASS】主数据 CRUD 排在一期周 1-2** — 位置正确。

### 维度 6 — 可测试性：【结论：FAIL】

1. **【FAIL §9 / 全文】无测试策略** — §9 完全没提测试，无分层、无覆盖率目标、无验收用例。计费/折旧/还款/30 天应付都是纯计算函数，理应有单元测试。
2. **【WARNING §7】各模块无 DoD / 验收标准** — 路线图每行只写"完成 X 模块"，没"怎么验"。
3. **【WARNING §3.3 / §3.4 / §5.3】关键计算逻辑缺端到端验证设计** — 庭宇测算 Excel 本可作对账基准，却被甩给二期。

**可否交付：不可直接交付开发。**

三大痛点的"骨架"立起来了，但作为财务系统在一期就漏掉了承重墙——计费/收入确认表、users 表、幂等与事务、软删除与冲红、审计日志、测试策略。这六条任何一个落下去，都会在上线第一个月要么算错账、要么改了无痕、要么重复触发污染资金池。

**最低修复门槛（开工前必改）**：
1. 补 `users`、`billings`、`audit_logs` 三表，补齐悬空外键
2. §3.2 加"幂等与事务策略"
3. 全表统一时间戳 + 软删除；约定 rate 单位；统一 direction
4. 审计日志 + 测试策略 + 历史数据初始化写进一期路线图
5. leasing_processes 加利率/期数/频率，还款计划放款自动生成
6. §9 加测试小节 + 每模块 DoD，以庭宇测算 Excel 作对账基准
