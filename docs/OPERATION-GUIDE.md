# SIEGPU 算力租赁 ERP — 全流程操作指引

> 版本：v3.3 · 2026-08-01 · 面向：**部署人员 + 4 个业务角色**
> 配套：设计书 `docs/superpowers/specs/2026-08-01-siegpu-erp-design-v3.md`、`2026-08-01-siegpu-wizard-workflow-design.md`；易用性评估 `2026-08-01-siegpu-usability-evaluation.md`；截图 `e2e/screenshots/`

本手册覆盖：**部署初始化 → 登录 → 业务全流程 → 向导式工作台 → 各模块操作 → 运维 → 排障**。

---

## 1. 系统简介

算力租赁业务小型 ERP，覆盖**签约→资金筹措→金租→放款→订货交付→运营（计费/发票/还款/折旧）**全生命周期，核心解决三大痛点：**资金池头寸、金租审批进度、合同发票对账**。

- 技术栈：FastAPI + Vue3 + PostgreSQL 16 + Docker
- 用户：3–5 人内网，浏览器访问
- 地址：前端 `http://<服务器>:8088`，后端接口 `http://<服务器>:8000/docs`
- **v3.2 核心交互**：建项目自动生成**向导式工作流**，首页待办按角色推送「立即处理」，工作台内**抽屉式逐步办理**（见 §6）。
- **v3.3 新增**：建项目可选**流程模板**（18 步标准金租 / 15 步自有全款）；资金池**分项目视图**（净头寸/可调余额/在途调配）+ 调配归还原生接 API；**项目总览 / 项目对比**两个组合视角页面；首页**预警卡**（8 条规则）；关键操作**审计留痕**（audit_logs，见 §5 附 B）。

## 2. 部署与初始化（部署人员）

### 2.1 启动
```bash
# 在仓库根目录
docker compose up -d --build
```
- 启动顺序：`db`（含健康检查）→ `backend`（启动时自动 `alembic upgrade head` 建表）→ `frontend`（nginx）。
- 首次启动会创建数据库卷并建全部业务表（由 Alembic 管理）。

### 4.1 设计中的权限矩阵

| 主数据（供应商/客户/设备/银行） | 读写 | 读写 | 读 | 读 |
| 项目 / 合同 | 读写 | 读写（采购） | 读 | 读 |
| 资金流水 | 读写 | 读 | 读 | 读写 |
| 跨项目调配 | 审批 | — | — | 发起 |
| 金租流程 | 读写 | 读 | 读写 | 读 |
| 订单 / 交付 / 验收 | 读写 | 读写 | 读写 | 读 |
| 计费 / 发票 / 客户确认 | 读写+审批 | 读 | 读 | 读写 |
| 还款 / 资产 | 读写 | 读 | 确认 | 读写 |
| 用户管理 / 审计日志 / 流程模板 | 读写（admin） | — | — | — |

### 4.2 工作台相关的权限分层（已落地）
- **首页待办按 `doer_role` 过滤**：只显示"当前步骤负责人角色 = 你的角色"的待办，别人角色的步骤不出现在你的首页。
- **跳过步骤**：可选步骤（模板里 `required=false`，如 Step 18 盈利测算）任何登录用户可跳过；**必做步骤仅财务总监（FINANCE_DIRECTOR）或管理员（ADMIN）可强制跳过**，其他人点了会被 403 拦下（提示"强制跳过必做步骤需要 FINANCE_DIRECTOR 或 ADMIN 权限"）。跳过必须填原因，写审计日志。
- **手动标记完成**（兜底通道）：**仅财务总监或管理员**，其余角色 403。
- **流程模板管理**：新建模板仅 ADMIN（`POST /api/workflows/templates`）；查看模板列表所有登录用户均可。

### 4.3 ⚠️ 当前实现状态（诚实说明）
> 除上述工作台权限点外，其余业务接口仍**只校验"已登录"，未按角色强制拦截**（即 4 个角色登录后都能操作所有模块）。4.1 矩阵是**设计目标**，按角色限权属待办项。在权限收紧前，请靠**操作规范 + 审计**约束（所有写操作都会留痕）。

## 5. 业务全流程操作（端到端剧本）

以一个新项目「商机5090」为例，按业务发生顺序操作。**建议严格按此顺序**，后续模块依赖前面的数据。建项目后也可以直接跟着**向导式工作台**（§6）逐步办理——二者数据完全互通。

### 步骤 0 · 准备主数据（采购对接人 / 一次性）
菜单「主数据」：
1. **供应商**：新增。把金租公司建为「资金供应商」类型（金租流程要用）；设备厂商建为「设备供应商」。
2. **客户**：新增下游承租客户。
3. **设备型号**：新增 GPU 型号（大卡/小卡/组网设备）。
4. **银行**：新增授信银行（含授信额度、流贷年利率，**存小数**如 `0.0435`）。

### 步骤 1 · 建项目与合同
1. 「业务 → 项目」：新增「商机5090」，填总投资，并在「**流程模板**」下拉中选择向导模板——「标准金租流程（18 步）」或「自有资金全款流程（15 步）」（远程加载自 `GET /api/workflows/templates`，默认 18 步）。**保存后系统按所选模板自动生成向导工作流**（Step 1「项目建立」自动标完成），首页待办随即出现下一步。
2. 「业务 → 合同」：
   - 新增**销售合同**（类型 SALES）：选项目、对方=客户、合同金额（**不含税**）、**月租（含税）**——计费靠它。
   - 新增**采购合同**（类型 PURCHASE）：选项目、对方=设备供应商。系统按类型自动判定方向（销售=应收/采购=应付）与对方类型。
   - 合同/订单表单的「项目 / 对方（客户/供应商）/ 设备型号」均为**远程下拉选择**（显示名称，无需手填 ID）；从工作台跳转时 URL 自动带 `?project_id=`，新建弹窗会**预填当前项目**。

### 步骤 2 · 销售订单与采购订单
1. 「销售订单」：「新增销售订单」——项目/销售合同/设备型号均下拉选择，填数量、月租/台（含税），总月租自动=数量×单价（可手改），填起止租日。
2. 「业务 → 订单」：新增采购订单——选项目/设备型号/数量/单价，系统算总额并**自动生成 6 个交付阶段**：订货→到货→压测→运输在途→上架→点亮。

### 步骤 3 · 资金筹措（财务专员）
「资金池」：
- 「记一笔」：录 **自有资金 IN**（20–30%）+ **银行流贷 IN**（70–80%）。也可直接在工作台 Step 6/7 的抽屉里录（表单预填好了来源与方向，见 §6.4）。
- 仪表盘「资金池余额」实时累加；各项目净头寸可在首页/报表看。
- **跨项目调配**：可在「分项目」Tab 的行内直接点「调配」（调出项目自动预填，见 §7 资金池行），或点「调配」弹窗——选调出/调入项目、金额、日期、说明，系统校验「可调余额」并自动生成一出/一入两条流水（**总余额不变**）。「归还」弹窗通过 `GET /api/capital/allocations` **列出全部未归还调配**（不再依赖本浏览器记录），选择后提交 `POST /api/capital/allocations/{id}/return`，生成「调入方 OUT + 调出方 IN」反向两条流水完成归还。流水表每行有「红冲」操作（二次确认，生成等额反向流水抵消，不可撤销）。

### 步骤 4 · 金租申请与放款（项目交付）
「金租流程」（**UI 已完整落地**）：
1. **新建申请**：页面右上「新建金租申请」——项目、金租公司（只列「资金供应商」）均下拉选择，填 **申请金额 / 年利率(小数) / 期数 / 还款频率（月/季/半年）/ 还款方式（等额本息·等额本金）/ 开始日期**。系统自动生成 **9 个标准节点**：接触→业务交流→资料提交→金租审核→一次上会→二次上会→访谈→批方案→放款。
2. **推进节点**：列表点「详情」打开抽屉，9 节点时间线上逐节点操作：「开始」（未开始→进行中）、「完成」、「卡住」（弹窗**必填原因**，时间线上红色显示原因）。
3. **放款**：详情抽屉下方「放款操作」填**实际放款额 + 放款日** → 「确认放款」。系统**同事务**自动：
   - 生成一条「金租融资 IN」资金流水（=实际放款额）；
   - 按 4 个参数**自动生成 N 期还款计划**（Σ本金=放款额，末期吸收尾差）；
   - **自动置换**：用放款归还该项目此前的流贷/自有垫付（生成置换记录）；
   - 申请状态置「已放款」，幂等（重复放款被拦）。
4. **还款确认**：放款后详情抽屉出现还款计划表，逐期「确认还款」——自动带入计划本息，填实际本息 + 付款日期，状态置「已还」。逾期会在首页预警。

### 步骤 5 · 验收（采购/交付）
「验收管理」：
1. 「新建验收」：选项目、**验收类型**（采购验收关联采购订单 / 销售验收关联销售订单，均下拉）、验收人、合格/不合格数量。
2. 列表行内对「待验收/验收中」的单据点「**通过**」或「**驳回**」（驳回弹窗**必填原因**）。
3. 也可在工作台 Step 11/13 的抽屉里办理：**创建验收单 → 上传附件（可选）→ 审批通过**三段链式提交（见 §6.4）。

### 步骤 6 · 交付推进与点亮（采购/交付）
「业务 → 订单」：点行内「详情」打开抽屉：
1. **交付阶段**区逐阶段推进（进行中→已完成）。
2. 全部就绪后点「**点亮上线**」，填点亮日。系统**同事务**自动生成**固定资产**记录（残值 10%、月折旧=应折旧额/60、折旧起=点亮日、止=+5 年）。**点亮日=计费起点**。

### 步骤 7 · 计费（财务专员）
「计费管理」：「生成计费」——选订单、销售合同（均下拉，可先选项目过滤订单）、**计费期数**、计费日期，为已点亮订单的销售合同**按期**生成应收：
- 首月按「剩余天数/当月总天数」比例计（含点亮当日），之后整月月租；
- 自动价税分离（不含税收入 + 税额），`(order_id, period_index)` 唯一防重复生成（重复提交提示"已存在"）；
- 生成终止：合同进入「已完成/已终止」或越过 `end_date` 后停止（实现侧校验）。
- 也可在工作台 Step 15 抽屉里生成（该项目订单/销售合同自动过滤，只有一条时自动选中）。

### 步骤 8 · 客户确认（财务专员）
「客户确认」：
- 确认单通常在工作台 Step 16 抽屉里创建（选计费单 + 销售订单 → 填客户确认人，链式 **创建→确认** 一步完成）。
- 本页面对「待确认」的单据行内操作：「**确认**」（弹窗必填**客户签字人**）或「**争议**」（弹窗必填争议原因，状态置「有争议」红色显示）。

### 步骤 9 · 发票、核销与对账（财务专员）
「发票/对账」：
- **开票**：「新增发票」关联合同、填含税金额（自动拆价税）；支持 **OCR 识别**（上传发票图片/PDF 自动填发票号/金额/日期，识别后请人工校验）。系统**拦截超开**：累计不含税 > 合同额×100.1% → 报错（需总监审批口径）。
- **收款/付款**：行内「收款/付款」按当天日期标记。
- **红冲**：行内「红冲」，原票置「已红冲」并建红冲凭证，对账自动剔除。⚠️ 当前点击即执行，无二次确认，请谨慎。
- **核销**（发票 ↔ 收款流水勾稽）：两条路径——①**工作台 Step 17 抽屉**：开票表单内选择该项目入金流水，链式执行 **开票 → 收款（填了收款日期才执行）→ 核销（选了流水才执行）**，未选流水时抽屉会提示并给出发票对账页跳转；②**发票/对账页「核销」行操作**：弹窗选择该项目入金流水提交勾稽，未全额核销时弹窗保持打开可继续选下一笔（⚠️ 弹窗内累计额为本次会话统计，精确累计字段 `matched_amount` 后端待补）。
- **对账页**（第二个 Tab）：三流勾稽表——**合同额 → 应收(计费) → 已开票 → 已收款**，逐级差异；有差额标橙。

### 步骤 10 · 还款（项目交付/财务）
见步骤 4 第 4 条：在「金租流程」详情抽屉的还款计划表逐期「确认还款」；接口 `GET/PATCH /api/repayments`。

### 步骤 11 · 资产、报表与利润测算（财务/总监）
- 「业务 → 资产」：查看点亮生成的资产；`GET /api/assets/{id}/depreciation-schedule` 看 60 期月折旧明细（Σ=应折旧额）。
- 「首页」：KPI（资金池余额/项目数/预警/月折旧合计）+ **待处理卡片**（§6.7）+ 资金月度趋势图 + 预警 + 项目概览。
- 报表接口：`/api/reports/capital-monthly`（资金月报）、`/project-overview`（项目概览）、`/receivables-aging`（应收账龄分桶）。
- 「利润测算」：左侧参数卡——**「按项目自动算」下拉选项目即自动取真实参数出结果**，或手动调参数后点「计算利润」。出结果后可：
  - 「**保存为场景**」：选归属项目、填场景名（如"V1 报价版"），把当前测算存底；
  - 「**设为实际**」：保存并标记为该项目实际口径对比基准（工作台 Step 18「盈利测算」以"存在实际场景"为完成条件）。
  - 结果含 IRR(年化)、NPV(5%贴现)、回本月、总税前利润等 KPI、累计现金流走势图与月度明细表。

### 附 A · 预警规则（首页预警卡）
- 接口 `GET /api/dashboard/alerts` 实时计算当前触发的预警，展示在**首页「预警」卡片**（KPI 区同时显示预警条数）；无预警时显示"暂无预警"。
- 当前共 **8 条规则**（v3.3 新增第 1/6/7/8 条），按级别 高危 / 警告 / 提示 分级：

| # | 规则 | 级别 | 触发条件 |
|---|---|---|---|
| 1 | 还款逾期 `REPAYMENT_OVERDUE` | 高危 | 还款计划到期日已过且状态「待还」 |
| 2 | 调配逾期未归还 `ALLOCATION_OVERDUE` | 警告 | 调配预计归还日已过且状态「已调配」 |
| 3 | 金租放款额不符 `DISBURSE_MISMATCH` | 警告 | 实际放款与申请额偏差 > 1% |
| 4 | 金租放款延迟 `DISBURSE_DELAY` | 高危 | 放款节点计划日已过仍未完成 |
| 5 | 资金池不足 `POOL_INSUFFICIENT` | 高危 | 池余额 < 未来 30 天应付（还款 + 应付发票） |
| 6 | 交付停滞 `DELIVERY_STUCK` | 警告 | 交付阶段「进行中」超 7 天未推进 |
| 7 | 合同到期 `CONTRACT_EXPIRING` | 提示 | 执行中合同 30 天内到期 |
| 8 | 工作流停滞 `WORKFLOW_STUCK` | 警告 | 进行中工作流超 14 天未更新 |

### 附 B · 审计留痕（audit_logs）
- 所有敏感写操作在业务事务内同步写入 `audit_logs` 表（`app/services/audit_service.py`），随业务提交**原子落库**；每条含 **操作人（user_id）/ 动作 / 对象类型与 ID / 变更前后 JSON（含金额等）/ 时间 / IP / request_id**。
- 当前留痕的 **10 类动作**：

| 动作 | 业务操作 |
|---|---|
| `CAPITAL_TXN` | 资金记一笔 |
| `ALLOCATE` | 跨项目调配 |
| `ALLOCATE_RETURN` | 调配归还 |
| `REVERSE` | 流水/发票红冲 |
| `DISBURSE` | 金租放款 |
| `SUPERSEDE` | 放款置换流贷/自有垫付 |
| `ACCEPT_APPROVE` | 验收审批 |
| `LIGHT_ON` | 点亮上线 |
| `RECONCILE` | 发票核销 |
| `CONFIRM_UPLOAD` | 客户确认 |

- 工作流步骤的完成/跳过/手动标记另有 `StepAuditLog`（见 §6.5）。
- ⚠️ **暂无审计查看 UI**：运营期需查审计时直接查库，例如：
  ```bash
  docker compose exec db psql -U siegpu -d siegpu \
    -c "SELECT at, action, entity_type, entity_id, user_id FROM audit_logs ORDER BY at DESC LIMIT 50;"
  ```

## 6. 向导式工作台（v3.2 核心）

### 6.1 是什么：建项目自动生成的"施工向导"
- 在「业务 → 项目」新增项目保存后，系统**自动为该项目生成一条工作流**：按表单「流程模板」下拉所选的模板生成（默认 18 步标准金租），Step 1「项目建立」自动标完成，`current_step` 指向下一步。
- 每个步骤定义了：负责人角色（`doer_role`）、完成检测条件（`completion_check`，系统自动判完成）、办理方式（**抽屉表单** or **跳转页面**）。
- **两个预置模板**（`python -m app.seed` 时写入，已存在则跳过）：

| 模板 | 步数 | 说明 |
|---|---|---|
| 标准金租流程（18步） | 18 | 完整链路：自有+流贷垫付→金租置换，覆盖项目建立到盈利测算 |
| 自有资金全款流程（15步） | 15 | 精简版：去掉 Step 6 银行流贷入金、Step 9 金租申请、Step 10 金租放款+置换 |

> ✅ **模板选择已开放（v3.3）**：建项目表单有「流程模板」下拉（远程加载 `GET /api/workflows/templates`），建项目接口接受 `template_id`，按所选模板生成工作流；不选默认 18 步标准金租模板。管理员可用 `POST /api/workflows/templates` 新建自定义模板。

### 6.2 标准 18 步一览
| # | 步骤 | 负责人角色 | 办理方式 |
|---|---|---|---|
| 1 | 项目建立 | 采购对接人 | 建项目时自动完成 |
| 2 | 销售合同 | 采购对接人 | 跳「业务→合同」 |
| 3 | 采购合同 | 采购对接人 | 跳「业务→合同」 |
| 4 | 销售订单 | 采购对接人 | 跳「销售订单」 |
| 5 | 采购订单 | 采购对接人 | 跳「业务→订单」 |
| 6 | 银行流贷入金 | 财务专员 | **抽屉**（入金表单，预填来源=银行流贷） |
| 7 | 自有资金入金 | 财务专员 | **抽屉**（入金表单，预填来源=自有资金） |
| 8 | 预付采购款 | 财务专员 | **抽屉**（出金表单） |
| 9 | 金租申请 | 项目交付 | 跳「金租流程」新建申请 |
| 10 | 金租放款+置换 | 财务总监 | 跳「金租流程」详情抽屉放款 |
| 11 | 采购验收 | 采购对接人 | **抽屉**（创建→上传附件→审批） |
| 12 | 交付6阶段 | 采购对接人 | 跳「业务→订单」详情推进 |
| 13 | 销售验收 | 项目交付 | **抽屉**（创建→上传附件→审批） |
| 14 | 点亮 | 采购对接人 | 跳「业务→订单」详情「点亮上线」 |
| 15 | 计费 | 财务专员 | **抽屉**（选订单+合同+期数） |
| 16 | 客户确认 | 财务专员 | **抽屉**（创建→客户确认） |
| 17 | 开票+回款+核销 | 财务专员 | **抽屉**（开票→收款→核销） |
| 18 | 盈利测算（可选） | 财务专员 | 跳「利润测算」保存场景/设为实际 |

> 注：Step 12 与 Step 14 的完成检测目前都以"订单已点亮"为条件——点亮后两步会先后判完成，若进度看似滞后一步，点「刷新进度」即可（见 6.6）。

### 6.3 入口
1. **首页「待处理」卡片**：列出"该你办"的步骤，点「**立即处理**」直达工作台。
2. 直接访问 `/projects/<项目ID>/workspace`。
3. **旧项目兼容**：没有工作流的项目（含 demo 载入的项目）首次打开工作台时，系统会**从存量业务数据自动反推进度**（幂等），已发生的环节直接显示完成。

### 6.4 界面与抽屉式办理
工作台页面自上而下：
- **进度条**：完成+已跳过 / 总步数的百分比，下方显示"X / 18 步完成 · 状态"。
- **当前步骤卡片**：步骤名、负责人角色、审批角色，右侧「标记完成」「跳过」，下方蓝色「**立即处理**」。
- **时间线**：全部步骤，状态圆点+符号（✓ 完成 / ⊘ 跳过 / ○ 待办，当前步骤蓝色高亮），显示负责人角色与完成日期。

点「立即处理」分两种：
- **抽屉步骤**（8 个）：右侧滑出 480px 抽屉表单，`{{project_id}}` 等预填值自动替换为当前项目：
  - **资金入金/出金**（Step 6/7/8）：来源、金额、日期（日期选择器）、摘要；
  - **验收**（Step 11/13）：类型已按步骤预填，**创建验收单 → 上传附件（可选，无附件自动跳过）→ 审批通过**三段链式提交，每段显示 待执行/执行中/已完成/已跳过/失败 状态，**某段失败保留已完成段，修正后点「重试」接着走**；
  - **计费**（Step 15）：下拉选该项目订单 + 销售合同（各只有一条时自动选中）、期数、计费日；
  - **客户确认**（Step 16）：选计费单（自动带期间标签）+ 销售订单 + 客户确认人，链式 创建→确认；
  - **开票+回款+核销**（Step 17）：填发票信息，**开票 → 收款（填了收款日期才执行）→ 核销（选了流水才执行）**；未选流水时提示可稍后到发票对账页完成并给出跳转。
- **页面步骤**：自动跳转对应业务页面（URL 带 `?project_id=xxx`）。
- 抽屉提交成功后**自动调用「刷新进度」并重载时间线**，完成条件满足的步骤立即变 ✓。

### 6.5 跳过与手动标记完成（权限分层）
- **跳过**：当前步骤卡片「跳过」→ 浏览器弹窗**必填原因**。**可选步骤**（模板中 `required=false`，18 步模板里只有 Step 18）任何登录用户可跳过；**必做步骤仅财务总监或管理员**可强制跳过，其余角色被 403 拦下并提示原因。跳过为终态（刷新不会回退），全部写审计日志。
- **手动标记完成**：当前步骤卡片「标记完成」——**仅财务总监或管理员**可用的兜底通道（数据已在系统外完成、检测条件覆盖不到时用），同样写审计日志（note 默认"手动标记完成"）。
- 每一步的完成/跳过/手动完成/推断都会写 `StepAuditLog`；工作流行级锁（SELECT FOR UPDATE）防两人同时推进。

### 6.6 刷新进度与红冲自动回退
- 页面右上「**刷新进度**」：对全部步骤重新跑完成检测——在外围页面（而非工作台抽屉）完成的操作，点一下即同步进度。
- **红冲回退**：某步已完成、但支撑数据随后被红冲/删除（如 Step 17 的发票被红冲后不再是"已核销"），刷新时该步会**自动从 ✓ 回退为待办**，`current_step` 跟着倒退。已跳过（⊘）的步骤是终态，不参与回退。

### 6.7 首页待办按角色过滤
- 「待处理」卡片的数据来自 `GET /api/workflows/my-tasks`：**只返回 当前步骤负责人角色 = 你角色 的进行中项目**，财务看不到采购的活，反之亦然。
- 卡片显示 项目名 / Step 序号与名称 / 负责人角色标签，点「立即处理」直达工作台。
- 首页待办**每 30 秒自动静默刷新**；工作台进入时自动全量重检，协作中也可随时点「刷新进度」手动重检。

## 9. 排障（FAQ）

| 现象 | 原因 / 处理 |
|---|---|
| **登录提示账号密码错误** | 多半是浏览器自动填充了**旧密码**。用无痕窗口或清站点密码，手动输 `sie123`。或硬刷新 `Ctrl+Shift+R`。 |
| **登录 200 但页面空白** | 前端构建/缓存问题。硬刷新；看 F12 控制台报错。 |
| **工作台步骤做完了但不打勾 / 不往下走** | 1) 先点工作台右上「**刷新进度**」全量重检；2) 检查数据是否真的满足完成条件——验收要「已通过」（只创建不算）、发票要「已核销」（只开票不算）、盈利测算要存在"实际场景"；3) Step 12/14 都以点亮为条件，点亮后需刷新才会连推。 |
| **跳过/标记完成报 403** | 权限分层：必做步骤的跳过、以及手动标记完成，**仅财务总监或管理员**；可选步骤（如 Step 18）的跳过人人可点。换 `cfo` 账号操作。 |
| **首页待办是空的** | 待办按角色过滤——当前步骤负责人是别的角色时你这里不显示（正常现象）；若确定该有，进一次项目工作台触发进度推断/刷新。 |
| **抽屉提交一半失败** | 验收/开票等链式表单**保留已完成子步骤**：修好报错（红字已显示在哪一段）后直接点「重试」，会从未完成的子步骤接着走。 |
| **开票报「超开」422** | 累计开票（不含税）超过合同额×100.1%。核对合同额与已开票；如属合理补充协议，需总监口径放宽（实现侧调整 tolerance）。 |
| **调配报「可调余额不足」422** | 调出项目净头寸不足。可调余额=净头寸正部；先给该项目注资或收回其它调配（资金池页「调配/归还」弹窗操作，见 §5 步骤 3）。 |
| **重复放款/点亮/计费被拦 409** | 幂等保护：同一申请/订单/期只能操作一次。属正常防重。 |
| **资金池余额"对不上"** | 1) 是否有软删除/红冲记录被算入（红冲会自动抵消）；2) 查 `/api/capital/summary` 的 `by_source` 与 `per_project` 对账。 |
| **页面接口 401** | token 过期（30 分钟）。重新登录即重新发 token。 |
| **字体显示为系统字体** | Web 字体（Sora 等）走 CN 镜像，若网络不通会回退系统字体；不影响功能。要保真可改本地打包字体。 |
