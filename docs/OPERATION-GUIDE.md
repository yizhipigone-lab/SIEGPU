# SIEGPU 算力租赁 ERP — 全流程操作指引

> 版本：v2.0 · 2026-07-31 · 面向：**部署人员 + 4 个业务角色**
> 配套：设计书 `docs/superpowers/specs/2026-07-30-siegpu-erp-design-v2.md`；截图 `e2e/screenshots/`

本手册覆盖：**部署初始化 → 登录 → 业务全流程 → 各模块操作 → 运维 → 排障**。

---

## 1. 系统简介

算力租赁业务小型 ERP，覆盖**签约→资金筹措→金租→放款→订货交付→运营（计费/发票/还款/折旧）**全生命周期，核心解决三大痛点：**资金池头寸、金租审批进度、合同发票对账**。

- 技术栈：FastAPI + Vue3 + PostgreSQL 16 + Docker
- 用户：3–5 人内网，浏览器访问
- 地址：前端 `http://<服务器>:8080`，后端接口 `http://<服务器>:8000/docs`

## 2. 部署与初始化（部署人员）

### 2.1 启动
```bash
# 在仓库根目录
docker compose up -d --build
```
- 启动顺序：`db`（含健康检查）→ `backend`（启动时自动 `alembic upgrade head` 建表）→ `frontend`（nginx）。
- 首次启动会创建数据库卷并建全部 19 张表（由 Alembic 管理）。

## 3. 登录

1. 浏览器打开 `http://<服务器>:8080/login`。
2. 输入账号 + 密码（`sie123`），点「登 录」。
3. 成功后跳转首页（仪表盘）。

**常见登不进的原因（重要）**：
- **浏览器自动填充了旧密码**——若之前用其它密码登过，浏览器密码管理器会回填旧密码。请在**无痕窗口**登录，或清除该站点的已保存密码后手动输 `sie123`。
- **缓存了旧前端**——按 `Ctrl+Shift+R` 硬刷新。
- 账号密码就是上表的 `sie123`，没有别的。

## 5. 业务全流程操作（端到端剧本）

以一个新项目「商机5090」为例，按业务发生顺序操作。**建议严格按此顺序**，后续模块依赖前面的数据。

### 步骤 0 · 准备主数据（采购对接人 / 一次性）
菜单「主数据」：
1. **供应商**：新增。把金租公司建为「资金供应商」类型（金租流程要用）；设备厂商建为「设备供应商」。
2. **客户**：新增下游承租客户。
3. **设备型号**：新增 GPU 型号（大卡/小卡/组网设备）。
4. **银行**：新增授信银行（含授信额度、流贷年利率，**存小数**如 `0.0435`）。

### 步骤 1 · 建项目与合同
1. 「业务 → 项目」：新增「商机5090」，填总投资。
2. 「业务 → 合同」：
   - 新增**销售合同**（类型 SALES）：选项目、对方=客户、合同金额（**不含税**）、**月租（含税）**——计费靠它。
   - 新增**采购合同**（类型 PURCHASE）：选项目、对方=设备供应商。系统按类型自动判定方向（销售=应收/采购=应付）与对方类型。

### 步骤 2 · 资金筹措（财务专员）
「资金池」：
- 「记一笔」：录 **自有资金 IN**（20–30%）+ **银行流贷 IN**（70–80%）。
- 仪表盘「资金池余额」实时累加；各项目净头寸可在首页/报表看。
- **跨项目调配**（API，UI 待补）：从 A 调到 B，系统校验「可调余额」并自动生成一出/一入两条流水（**总余额不变**）。

### 步骤 3 · 金租申请与放款（项目交付）
「金租流程」（UI 列表/详情待补，接口已就绪，可用 `/api/leasing/*` 或前端补页）：
1. **建申请**：选项目 + 金租公司（资金供应商）+ 融资额，并填 **年利率 / 期数 / 还款频率（季/月/半年）/ 还款方式（等额本息·等额本金）**。系统自动生成 **9 个标准节点**：接触→业务交流→资料提交→金租审核→一次上会→二次上会→访谈→批方案→放款。
2. **推进节点**：按实际进度把节点状态改为「进行中→已完成」，卡住的标「卡住」+ 原因。
3. **放款**（一键）：`POST /api/leasing/processes/{id}/disburse`，填**实际放款额 + 放款日**。系统**同事务**自动：
   - 生成一条「金租融资 IN」资金流水（=实际放款额）；
   - 按 4 个参数**自动生成 N 期还款计划**（Σ本金=放款额，末期吸收尾差）；
   - 申请状态置「已放款」，幂等（重复放款被拦）。

### 步骤 4 · 订货与交付点亮（采购/交付）
「业务 → 订单」：
1. 新增订单：选项目/设备型号/数量/单价，系统算总额并**自动生成 6 个交付阶段**：订货→到货→压测→运输在途→上架→点亮。
2. 推进各阶段状态。
3. **点亮**（`POST /api/orders/{id}/light-on`）：填点亮日。系统**同事务**自动生成**固定资产**记录（残值 10%、月折旧=应折旧额/60、折旧起=点亮日、止=+5 年）。**点亮日=计费起点**。

### 步骤 5 · 计费（财务专员）
计费接口 `POST /api/billings`：为已点亮订单的销售合同**按期**生成应收：
- 首月按「剩余天数/当月总天数」比例计（含点亮当日），之后整月月租；
- 自动价税分离（不含税收入 + 税额），`(order_id, period_index)` 唯一防重复生成。
- 生成终止：合同进入「已完成/已终止」或越过 `end_date` 后停止（实现侧校验）。

### 步骤 6 · 发票与对账（财务专员）
「发票/对账」：
- **开票**：`POST /api/invoices`，关联合同、填含税金额（自动拆价税）。系统**拦截超开**：累计不含税 > 合同额×100.1% → 报错（需总监审批口径）。
- **收款**：`POST /api/invoices/{id}/pay` 标记收款日。
- **红冲**：`POST /api/invoices/{id}/reverse`，原票置「已红冲」并建红冲凭证，对账自动剔除。
- **对账页**：三流勾稽表——**合同额 → 应收(计费) → 已开票 → 已收款**，逐级差异；有差额标橙、状态「未回款/已结清」。

### 步骤 7 · 还款（项目交付/财务）
`GET/PATCH /api/repayments`：放款时已自动生成 N 期计划；逐期「确认还款」填实际本息 + 付款日，状态置「已还」。逾期会在首页预警。

### 步骤 8 · 资产与报表（财务/总监）
- 「业务 → 资产」：查看点亮生成的资产；`GET /api/assets/{id}/depreciation-schedule` 看 60 期月折旧明细（Σ=应折旧额）。
- 「首页」：KPI（资金池余额/项目数/预警/月折旧合计）+ 资金月度趋势图 + 预警 + 项目概览。
- 报表接口：`/api/reports/capital-monthly`（资金月报）、`/project-overview`（项目概览）、`/receivables-aging`（应收账龄分桶）。

## 7. 数据与运维（部署人员）

### 7.1 备份恢复
```bash
# 每日备份（建议 cron）
docker compose exec db pg_dump -U siegpu siegpu > backups/siegpu-$(date +%F).sql
# 恢复到测试库验证
docker compose exec -T db psql -U siegpu -d siegpu_test < backups/siegpu-XXXX.sql
```
建议：RPO≤24h，每季度做一次恢复演练。

### 7.2 数据库迁移（Alembic）
- 表由 Alembic 管理，backend 启动自动 `alembic upgrade head`。
- **加字段/表**：改 `app/models/` 后，`docker compose exec backend alembic revision --autogenerate -m "xxx"` → 检查生成的迁移 → `alembic upgrade head`。
- 已验证模型与 DB **零 drift**（`alembic revision --autogenerate` 产出空迁移）。
- ⚠️ 索引/触发器/CHECK 由 baseline 管理，autogenerate 不检测（`env.py` 已配 `include_object` 跳过索引），新增索引需手写进迁移。

### 7.3 重启 / 日志
```bash
docker compose restart backend
docker compose logs -f backend
```

### 7.4 Excel 导入导出
- 导出：`GET /api/excel/export/{suppliers|customers|capital_transactions}` → 下载 xlsx。
- 导入：`POST /api/excel/import/{suppliers|customers}`（上传 xlsx，表头用导出模板）。

## 8. 排障（FAQ）

| 现象 | 原因 / 处理 |
|---|---|
| **登录提示账号密码错误** | 多半是浏览器自动填充了**旧密码**。用无痕窗口或清站点密码，手动输 `sie123`。或硬刷新 `Ctrl+Shift+R`。 |
| **登录 200 但页面空白** | 前端构建/缓存问题。硬刷新；看 F12 控制台报错。 |
| **开票报「超开」422** | 累计开票（不含税）超过合同额×100.1%。核对合同额与已开票；如属合理补充协议，需总监口径放宽（实现侧调整 tolerance）。 |
| **调配报「可调余额不足」422** | 调出项目净头寸不足。可调余额=净头寸正部；先给该项目注资或收回其它调配。 |
| **重复放款/点亮/计费被拦 409** | 幂等保护：同一申请/订单/期只能操作一次。属正常防重。 |
| **资金池余额"对不上"** | 1) 是否有软删除/红冲记录被算入（红冲会自动抵消）；2) 查 `/api/capital/summary` 的 `by_source` 与 `per_project` 对账。 |
| **页面接口 401** | token 过期（30 分钟）。重新登录即重新发 token。 |
| **字体显示为系统字体** | Web 字体（Sora 等）走 CN 镜像，若网络不通会回退系统字体；不影响功能。要保真可改本地打包字体。 |
