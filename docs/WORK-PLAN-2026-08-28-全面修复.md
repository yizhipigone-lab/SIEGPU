## 四、风险与对策

0. **schema 一致性（全阶段）**：任何模型变更（S3 建表 / S11 加列 / S12 删字段）必须同步 `backend/db/schema.sql`，并在该阶段跑 `test_migration_parity` 回归（仓库用该测试锁定迁移与 schema 一致）。
1. **预付款收敛动 D2 裁定**（高）：S3 一次性完成"表+落账+回填+台账页+双轨页"，避免中间态；回填先于台账页切换。
2. **直付负债科目假设**（中）：科目码可配置常量 + 文档标注，财务确认后一行改。
3. **前端批量改动 build 回归**（中）：每个阶段结尾跑 build；S1/S5 涉及多处 UI，优先。
4. **e2e 基线依赖旧流程**（中）：S5 后更新 e2e_full_flow 或新增 sales-order 路径，S13 统一跑。
5. **状态机/审批/收入口径三不改为硬约束**：改动全部落在"展示、报错、透传、新表、新接口"，不动核心转换规则。
